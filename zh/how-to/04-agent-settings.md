## 概述

智能体高级设置提供了对智能体的全面配置能力，涵盖提示词工程、模型参数、知识库检索策略、联网搜索、附件处理、工具调用和技能扩展等方面。合理配置这些选项可以显著提升智能体的回答质量和用户体验。

本文详细介绍智能体编辑器中每个配置分组的含义和使用建议。

---

## 前置条件

- 已登录睿阁，且当前账号为企业创建者或企业管理员。
- 已创建或正在创建一个智能体（参见 [智能体管理](/zh/how-to/03-agent)）。
- 如需关联知识库，至少需要一个已创建的知识库（参见 [知识库管理](/zh/how-to/01-knowledge-base)）。

---

## 左侧导航结构

智能体编辑器为全屏模态弹窗，左侧导航分为三个分组：

**基础**：
- 基本信息
- 提示词
- 模型配置
- 多轮对话（仅快速回答模式显示）
- 问题推荐

**知识检索**：
- 知识库
- 检索策略
- 网络搜索

**能力扩展**：
- 附件上传
- 工具配置（仅智能推理模式显示）
- 技能 Skills（仅智能推理模式 + 后端沙箱已启用时显示）

## 操作步骤

### 1. 基本信息

| 配置项 | 是否必填 | 说明 |
| --- | --- | --- |
| 智能体 ID | 只读 | 仅编辑模式显示，带复制功能 |
| 运行模式 | **是** | 快速回答 或 智能推理（单选） |
| 智能体类型预设 | 否 | 仅智能推理模式显示，可选 RAG 问答 / Wiki 问答 / Wiki + RAG 混合 / 自定义 |
| 名称 | **是** | 带头像预览，长度不超过 255 个字符，超过会提示"智能体名称长度不能超过255个字符" |
| 描述 | 否 | 智能体功能描述 |

**运行模式对比**：

| 模式 | 说明 | 适用场景 |
| --- | --- | --- |
| 快速回答 | 基础 RAG 问答，无工具调用，强调知识库检索 + 提示词控制 | 常见问题问答、客服机器人 |
| 智能推理 | Agent 模式，支持工具调用、多步推理、反思、Skills 等高级能力，界面描述为"多步思考，深度分析复杂问题" | 复杂研究、深度分析、多步骤任务 |

### 2. 提示词配置

提示词是智能体的"指令说明书"，告诉智能体如何回答用户问题。不同类型的提示词控制智能体在不同场景下的行为。

#### 系统提示词

| 配置项 | 说明 |
| --- | --- |
| 内容 | 定义智能体的角色、行为准则和回答风格，是智能体的"人设"和"工作守则" |
| 必填性 | 非内置智能体时必填，保存时校验并提示"请输入系统提示词"；内置智能体留空则使用系统默认提示词 |
| 可用变量 | 支持 `{{变量名}}` 格式插入，输入 `{{` 时弹出变量提示下拉框；可用变量显示在输入框上方，点击可直接插入，如 web_search_status（网络搜索状态）、knowledge_base_info（知识库信息）等 |
| 模板选择器 | 位于输入框右下角，可选择预设模板快速开始；智能推理模式使用 agentSystemPrompt 模板类型，快速回答模式使用 systemPrompt 模板类型 |
| 恢复默认 | 点击后恢复到系统默认提示词 |

> 提示：配置建议——明确角色定位（如"你是一个专业的客服助手"）、回答要求（如"使用简洁专业的语言"）、禁止行为（如"不要编造信息"）。

#### 上下文模板（仅快速回答模式）

| 配置项 | 说明 |
| --- | --- |
| 内容 | 定义如何将检索到的知识库内容格式化后传递给模型 |
| 必填性 | 非内置智能体时必填；内置智能体留空则使用系统默认模板 |
| 可用变量 | 支持 `{{context}}` 等变量插入 |

#### 意图提示词（仅快速回答模式）

针对不同类型的用户意图使用专门的提示词，让智能体在不同场景下给出更合适的回答。

| 意图 | 说明 |
| --- | --- |
| greeting | 问候回复 |
| chitchat | 闲聊回复 |
| follow_up | 追问回复 |
| image_only | 图片分析回复 |
| summarize | 总结回复 |
| web_search | 网络搜索不可用回复 |
| doc_only | 文档分析回复 |

> 提示：支持多意图切换（按钮组），每个意图可独立自定义提示词。已自定义的意图会在按钮上显示小圆点标记。

#### 改写提示词（仅快速回答模式 + 多轮对话开启 + 问题改写开启）

在多轮对话中自动改写用户问题，消解指代（如"它"→具体对象）和补全省略，提高检索准确性。

| 配置项 | 说明 |
| --- | --- |
| 改写系统提示词 | 定义改写任务的角色和规则 |
| 改写用户提示词 | 必须包含 `{{query}}` 占位符，否则保存失败 |

#### 检索兜底（仅快速回答模式 + 有知识库时）

当知识库检索未找到相关内容时，控制智能体如何回应。

| 策略 | 说明 |
| --- | --- |
| 固定回复 | 使用固定文本回复，适合统一话术（如"抱歉，我暂时无法回答这个问题"） |
| 模型生成（默认） | 使用 LLM 生成回复，适合灵活回应 |

### 3. 模型配置

| 配置项 | 是否必填 | 说明 |
| --- | --- | --- |
| 模型 | **是** | 选择智能体使用的大语言模型（类型 KnowledgeQA），创建时自动选择默认 KnowledgeQA 模型或第一个可用模型；点击 + 可前往全局设置添加模型 |
| 温度 | — | 范围 0-1，步长 0.1，默认 0.7。值越高输出越随机 |
| 最大生成 Token 数 | — | 范围 100-100000，默认 2048（仅快速回答模式） |
| 思考模式 | — | 开关，默认关闭。启用模型的扩展思考能力（需模型支持） |
| 输出来源引用 | — | 开关，默认开启。在最终回答中展示知识库和网页来源；关闭后仍会正常检索和使用证据 |
| 重排序模型 | 有 RAG 知识库时必填 | 有知识库时显示，类型 Rerank。对检索结果进行重排序以提高相关性 |

**智能推理模式专属配置**：

| 配置项 | 说明 |
| --- | --- |
| 最大迭代次数 | 范围 1-50，默认 10。Agent 执行推理的最大步数 |
| LLM 调用超时 | 范围 0-3600 秒，默认 120 秒 |

**问题理解模型**（仅快速回答模式 + 多轮对话开启 + 问题改写开启时显示）：

- 用于问题改写的专用模型，留空则复用主对话模型。

---

### 4. 多轮对话（仅快速回答模式）

| 配置项 | 说明 |
| --- | --- |
| 多轮对话 | 开关，默认关闭。开启后将保留历史对话上下文 |
| 保留轮数 | 范围 1-20，默认 5。保留最近几轮对话作为上下文 |
| 问题改写 | 开关，默认开启。多轮对话时自动改写用户问题 |

> 提示：智能推理模式始终支持多轮对话（后端强制启用），不显示此开关。

### 5. 问题推荐

配置智能体在对话中自动推荐的问题，帮助用户更好地探索知识库内容。

#### 开场推荐

| 配置项 | 说明 |
| --- | --- |
| 展示开场问题 | 开关，默认开启。在用户首次提问前展示引导性问题 |
| 内容来源 | 运营配置 / 知识库 / 混合（默认）。混合模式下优先展示配置的问题（最多占约 2/3），其余由知识库补充 |
| 展示数量 | 范围 1-8，默认 6 |
| 运营配置问题 | 手动编写固定问题，最多 8 条，每条最大 200 字符 |

#### 回答后推荐

| 配置项 | 说明 |
| --- | --- |
| 生成回答后推荐 | 开关，默认关闭。每次回答结束后异步生成追问建议 |
| 来源内容 | 模型生成 / 知识库 / 混合（默认） |
| 展示数量 | 范围 1-5，默认 3 |
| 生成模型 | 非知识库来源时显示。留空时使用本轮对话模型 |

**高级生成设置**：

| 配置项 | 说明 |
| --- | --- |
| 上下文轮次 | 范围 1-5，默认 2。生成追问时参考的历史对话轮数 |
| 问题类型 | 多选：澄清、深入、下一步（默认全选） |
| 附加生成要求 | 最多 2000 字，自定义追问生成的风格和方向 |

**展示与兜底规则**：

| 规则 | 默认状态 | 说明 |
| --- | --- | --- |
| 兜底回答后不展示 | 开启 | 触发兜底回复时不显示追问建议 |
| 回答以提问结尾时不展示 | 开启 | 避免问题套问题 |
| 生成失败时使用知识库候选 | 开启 | 保证追问建议始终可用 |
| 允许用户换一批 | 关闭 | 允许用户刷新追问建议 |

### 6. 知识库

配置智能体可访问的知识库范围与 FAQ 策略。企业智能体的知识范围统一为全部可见知识库。

> 注意：智能体检索的知识库白名单与当前用户可见集同源。对话中显式指定未授权的个人知识库检索时返回 403 拦截，不降级为全量检索、不返回任何片段。

**知识库选择模式**：

| 模式 | 说明 | 适用场景 |
| --- | --- | --- |
| 全部（默认） | 使用所有可用知识库 | 通用问答助手 |
| 选择 | 手动选择特定知识库 | 特定领域助手 |
| 不使用 | 禁用知识库检索 | 纯模型对话 |

> 注意：企业版锁定为全部，无法切换。

**指定知识库列表**（仅「选择」模式显示）：

- 支持多选，可过滤搜索。
- 分组显示：我的知识库 / 协作知识库。
- 每个知识库显示 RAG/Wiki 标签和文档数量。
- 不兼容的知识库会灰显（根据智能体工具推导的能力过滤）。

**支持的文件类型**（有知识库时显示）：

- 多选，可清空。可选项：PDF、Word、Text、Markdown、CSV、Excel、Image。
- 默认为空（不限制，即全部文件类型）；留空表示支持所有类型。

**仅在提及时检索**（有知识库时显示）：

- 开关，默认关闭。关闭时自动检索已配置的知识库，开启后仅当用户 @ 提及知识库时才检索，减少不必要的检索。

---

### 7. 检索策略

配置知识库检索的召回、排序与 FAQ 优先策略。

| 配置项 | 说明 |
| --- | --- |
| 查询扩展 | 开关，默认开启（仅快速回答模式）。自动扩展查询词以提高召回率，仅当初始检索结果较少时触发 |
| 向量召回数量 | 范围 1-50，默认 10。建议 10-20 |
| 关键词阈值 | 范围 0-1，默认 0.3。关键词检索的最低匹配分数 |
| 向量阈值 | 范围 0-1，默认 0.5。向量检索的最低相似度阈值 |
| 重排数量 | 范围 1-20，默认 5（需配置 Rerank 模型时显示）。重排序后进入答案生成的文档数量 |
| 重排阈值 | 范围 -10 到 10，默认 0.5（需配置 Rerank 模型时显示）。重排序阶段的最低得分阈值 |

**FAQ 优先策略**（有 FAQ 类型知识库时显示）：

| 配置项 | 说明 |
| --- | --- |
| 启用 FAQ 优先 | 开关，默认开启。FAQ 答案将优先于普通文档被引用 |
| 直接回答阈值 | 范围 0.7-1，默认 0.9（FAQ 优先开启时显示）。当问题与 FAQ 相似度超过此值时，直接使用 FAQ 答案 |
| FAQ 分数加权 | 范围 1-2，默认 1.2x（FAQ 优先开启时显示）。FAQ 结果的相关性分数乘以此系数，使其排序更靠前 |

**启用表格数据分析**（仅快速回答模式）：

- 开关，默认关闭。命中 CSV/Excel 类文件时，先调用大模型生成 DuckDB SQL 进行统计或筛选，再据此回答。
- 注意：会额外增加一次模型调用与几秒延迟。

### 8. 联网搜索

配置智能体的网络搜索能力，让智能体可以获取实时互联网信息。

| 配置项 | 说明 |
| --- | --- |
| 网络搜索 | 开关，默认关闭。启用后智能体可搜索互联网获取信息 |
| 搜索引擎 | 选择搜索引擎，可清空，留空则使用系统默认（从系统设置中已配置的搜索提供商中选择） |
| 最大搜索结果数 | 范围 1-10，默认 5。建议 3-5 |
| 自动抓取页面内容 | 开关。Rerank 后自动抓取排名靠前的网页完整内容，提升回答质量 |
| 抓取页面数 | 范围 1-10。Rerank 后最多抓取几个网页的完整内容，建议 2-3 |

> 提示：联网搜索会产生额外的搜索 API 调用成本。自动抓取页面内容会增加网络请求和处理时间。

### 9. 附件上传

配置对话中图片、文档、音频等附件的上传、解析及对应模型。

#### 图片上传

| 配置项 | 说明 |
| --- | --- |
| 图片上传 | 开关，默认关闭。启用后用户可在对话中上传图片并由 VLM 理解 |
| VLM 模型 | 启用时必填，类型 VLLM。用于图片分析的视觉语言模型 |
| 附件图片理解/扫描件 OCR | 开关，默认关闭。对图片型 PDF/PPT 等扫描件用 VLM 进行 OCR 识别 |
| 扫描件 OCR 最大页数 | 范围 0-64，默认 0（使用全局默认） |
| 图片存储 | 选择图片文件的存储引擎，可清空，留空则使用系统默认 |

#### 语音上传

| 配置项 | 说明 |
| --- | --- |
| 语音上传 | 开关，默认关闭。启用后用户可在对话中上传音频文件，系统使用 ASR 模型自动转录为文字 |
| ASR 模型 | 启用时显示，类型 ASR。用于音频转录的语音识别模型，未配置时音频文件将以占位符形式传递 |

#### 通用配置

| 配置项 | 说明 |
| --- | --- |
| 附件解析等待超时 | 范围 0-600 秒，默认 0（使用全局默认）。单轮问答等待附件解析完成的最长时间，超时后未完成的附件会被跳过 |
| 聊天附件解析策略 | 为不同文件类型指定解析引擎，仅对当前智能体的聊天附件生效，与知识库解析引擎配置独立、互不影响 |

**聊天附件解析策略——文件类型与解析引擎对照**：

| 文件类型分组 | 扩展名 | 可选解析引擎 |
| --- | --- | --- |
| PDF 文档 | pdf | 内置（默认）、mineru、mineru_cloud、paddleocr_vl、paddleocr_vl_cloud、markitdown、opendataloader |
| Word 文档 | doc、docx | 内置（默认）、mineru、mineru_cloud、markitdown |
| 演示文稿 | pptx | mineru、mineru_cloud（默认）、markitdown |
| Excel 表格 | xls、xlsx | 内置（默认）、markitdown |
| 电子书 | epub | 内置（默认） |
| 网页归档 | mhtml | 内置（默认） |
| CSV 文件 | csv | simple（默认）、markitdown |
| Markdown | md、markdown | 内置（默认）、simple、markitdown |
| 纯文本 | txt | simple（默认） |
| JSON 文件 | json | simple（默认） |
| 图片 | jpg、jpeg、png、gif | 内置（默认）、simple、mineru、mineru_cloud、paddleocr_vl、paddleocr_vl_cloud |

### 10. 工具配置（仅智能推理模式）

配置 Agent 可以调用的工具（Checkbox 多选），工具按分组渲染为卡片网格。

- 从普通模式切换到智能推理模式时，自动勾选基础工具：thinking、todo_write、knowledge_search。
- 工具可用性根据作用域内知识库能力动态判定，缺少对应能力的工具会被禁用并显示原因。
- 工具区域顶部显示能力状态：RAG 知识库数量、Wiki 知识库数量、不可用工具数量。

> 提示：工具越多，token 消耗越大。每次对话会将工具定义传给模型，建议根据实际需求选择。

#### 基础工具

| 工具 | 说明 |
| --- | --- |
| thinking（思考） | 动态和反思性的问题解决思考工具，适合复杂推理和多步骤问题 |
| todo_write（制定计划） | 创建结构化的研究计划，适合多步骤任务和项目规划 |

#### 知识库检索工具（RAG）

| 工具 | 说明 |
| --- | --- |
| grep_chunks（关键词搜索） | 快速定位包含特定关键词的文档和分块 |
| knowledge_search（语义搜索） | 理解问题并查找语义相关内容 |
| list_knowledge_chunks（查看文档分块） | 获取文档完整分块内容 |
| query_knowledge_graph（查询知识图谱） | 从知识图谱中查询实体间关系 |
| get_document_info（获取文档信息） | 查看文档元数据 |
| database_query（查询数据库） | 查询数据库中的结构化信息 |

#### Wiki 读取工具

| 工具 | 说明 |
| --- | --- |
| wiki_search（搜索 Wiki） | 在 Wiki 知识库中按关键词/语义搜索页面 |
| wiki_read_page（阅读 Wiki 页面） | 读取指定 Wiki 页面的完整内容 |
| wiki_read_source_doc（精读源文档） | 通过知识点深入阅读 Wiki 页面背后的原始文档 |
| wiki_flag_issue（标记 Wiki 问题） | 标记页面中存在的事实错误或合并冲突问题 |

#### Wiki 编辑工具（危险操作，会修改 Wiki 内容）

| 工具 | 说明 |
| --- | --- |
| wiki_write_page（创建/覆盖 Wiki） | 创建新页面或完全覆盖已有 Wiki 页面 |
| wiki_replace_text（局部替换 Wiki） | 替换 Wiki 页面中的特定文本 |
| wiki_rename_page（重命名 Wiki） | 重命名 Wiki 页面并自动更新关联链接 |
| wiki_delete_page（删除 Wiki） | 删除 Wiki 页面并自动清理关联死链 |

#### Wiki 巡检工具

| 工具 | 说明 |
| --- | --- |
| wiki_read_issue（查看 Wiki 问题） | 查看特定 Wiki 页面的巡检问题详情，包括问题类型、描述、状态 |
| wiki_update_issue（更新 Wiki 问题） | 更新 Wiki 页面问题的处理状态，便于跟踪和管理 |

#### 数据分析工具

| 工具 | 说明 |
| --- | --- |
| data_analysis（数据分析） | 理解数据文件并进行数据分析，支持 CSV/Excel |
| data_schema（查看数据元信息） | 查看数据表结构和字段含义 |

**工具选择建议**：

| 场景 | 推荐工具 |
| --- | --- |
| 通用问答助手 | 思考 + 制定计划 + 关键词搜索 + 语义搜索 |
| 深度研究助手 | 上述 + 查看文档分块 + 查询知识图谱 + 获取文档信息 |
| Wiki 知识库 | 思考 + 制定计划 + 搜索 Wiki + 阅读 Wiki 页面 + 精读源文档 |
| Wiki 管理助手 | 上述 + Wiki 编辑类 + Wiki 巡检类 |
| 数据分析助手 | 思考 + 查看数据元信息 + 数据分析 + 查询数据库 |

> 注意：Wiki 编辑类工具会直接修改 Wiki 内容，建议只在需要时开启。缺少对应知识库能力的工具会被禁用并显示原因；已勾选但无法生效的工具会在顶部显示警告提示。

**最终启用的工具**：

根据当前配置计算，是智能体保存后实际能调用的工具集合：

- 用户勾选且当前配置下可用的工具：正常显示。
- 用户勾选但当前配置下无法生效的工具：灰显并显示原因（如"需要关联启用 Wiki 能力的知识库"）。
- 开启联网搜索时：自动添加"网络搜索"和"网页抓取"工具。
- 空状态提示：当前没有可用工具，智能体将退化为纯模型问答。

**工具配置对知识库选择、文件选择和对话生成结果的影响**：

工具配置不仅决定智能体能调用哪些能力，还直接影响对话时的可选知识库范围、文件范围和对话生成结果。

对知识库选择的影响（知识库选择模式为"全部"时，工具配置决定哪些知识库会被过滤）：

| 工具类型 | 知识库必须具备的能力 | 说明 |
| --- | --- | --- |
| RAG 工具（knowledge_search、grep_chunks 等） | 向量检索或关键词检索 | 无 RAG 能力的知识库会被过滤 |
| Wiki 工具（wiki_search、wiki_read_page 等） | Wiki 索引 | 未启用 Wiki 的知识库会被过滤 |
| 基础工具（thinking、todo_write） | 无要求 | 不影响知识库过滤 |

过滤规则：知识库必须具备至少一种被已选工具要求的能力。例如只选 Wiki 工具时只显示启用 Wiki 的知识库；只选 RAG 工具时只显示启用向量或关键词检索的知识库；同时选了 Wiki 和 RAG 工具时显示启用 Wiki 或启用向量/关键词检索的知识库。

对文件选择的影响（决定对话时 @ 提及中是否显示文件分组）：

| 工具配置 | 文件分组是否显示 | 说明 |
| --- | --- | --- |
| 包含 RAG 工具（knowledge_search 等） | 显示 | RAG 工具支持消费文件引用 |
| 仅 Wiki 工具（wiki_search 等） | 不显示 | Wiki 工具不支持消费文件引用 |
| 仅基础工具（thinking、todo_write） | 显示 | 宽松回退，无工具要求时默认显示 |

对对话生成结果的影响：

| 工具 | 对对话结果的影响 |
| --- | --- |
| thinking（思考） | 模型会在回答前进行内部思考，提高回答质量 |
| todo_write（制定计划） | 模型会创建任务清单，跟踪进度 |
| knowledge_search（语义搜索） | 模型会进行语义搜索，基于知识库内容回答 |
| grep_chunks（关键词搜索） | 模型会进行关键词搜索，快速定位相关内容 |
| wiki_search（搜索 Wiki） | 模型会在 Wiki 中搜索相关页面 |
| web_search（网络搜索） | 模型会搜索互联网获取实时信息 |

工具不可用时的行为：工具被禁用（缺少对应知识库能力）时，模型无法使用该工具，会使用其他可用工具；所有工具都不可用时，智能体退化为纯模型问答，不依赖知识库。

### 11. 技能 Skills（仅智能推理模式 + 后端沙箱已启用）

Skills（技能）是遵循渐进式披露模式的模块化能力扩展单元，为 Agent 提供特定领域的专业知识、工作流程指令和可执行脚本。每个 Skill 以目录形式存在于后端文件系统中，核心文件为 `SKILL.md`（YAML frontmatter + Markdown 正文），Agent 在对话过程中按需加载相关 Skill 的指令内容。

**Skills 的三级加载机制**：

| 层级 | 名称 | 内容 | 加载时机 |
| --- | --- | --- | --- |
| Level 1 | Metadata（元数据） | Skill 名称（name）和描述（description） | 启动时发现并缓存，始终可用 |
| Level 2 | Instructions（指令） | SKILL.md 正文（frontmatter 之后的 Markdown 内容） | Agent 对话中需要该 Skill 时按需加载 |
| Level 3 | Resources（资源） | Skill 目录下的额外文件（如脚本、模板等） | Agent 执行具体任务时按需读取 |

**SKILL.md 文件格式规范**：

- 必须以 YAML frontmatter（`---` 分隔符）开头，`name` 和 `description` 均为必填。
- `name`：仅限 Unicode 字母、数字和连字符，最长 64 字符，不能包含 XML 标签。
- `description`：最长 1024 字符，不能包含 XML 标签。
- frontmatter 之后的 Markdown 正文为 Level 2 指令内容。

**Skills 选择模式**：

| 模式 | 说明 |
| --- | --- |
| 全部 | 使用所有可用 Skills |
| 指定 | 手动选择特定 Skills |
| 不使用（默认） | 不使用 Skills |

**当前预装技能列表**：

| 技能名称 | 说明 |
| --- | --- |
| 引用生成器 | 自动生成规范引用格式，支持 APA、MLA、Chicago 等多种格式 |
| 数据处理器 | 数据处理与分析，支持 Python 脚本执行进行高级数据处理 |
| 文档协作 | 引导用户通过结构化的文档共同编写工作流程 |
| 文档分析器 | 深度分析文档结构和内容，进行内容质量评估 |
| openmaic-classroom | 将 RAG 检索结果转换为 OpenMAIC 互动课程 |

**自定义技能**：

自定义技能通过向后端 Skills 搜索目录中添加包含 `SKILL.md` 的子目录实现，无需修改代码。Docker 部署时将技能目录挂载到容器的 `/app/skills/preloaded/` 路径下即可，无需重建镜像，重启容器后自动发现新技能。目录结构示例：

```
<skill-name>/                # 技能目录名（建议与 name 字段一致）
├── SKILL.md                 # 必须，技能定义文件
├── scripts/                 # 可选，可执行脚本目录（在沙箱中执行）
└── references/              # 可选，参考文档目录（Agent 按需读取）
```

沙箱启用时会自动注册两个 Skill 工具：`read_skill`（读取 Skill 指令内容或目录中的额外文件）和 `execute_skill_script`（在沙箱中执行 Skill 目录中的脚本）。

**在对话中使用 Skills**：

- 输入框支持 `@` 触发提及下拉，其中包含 Skills 分组。
- 可 @ 提及的 Skill 列表受智能体配置的 Skills 选择模式约束：
  - 不使用（none）模式：Skills 分组不显示，无法 @ 提及。
  - 指定（selected）模式：仅显示该智能体已选的 Skills。
  - 全部（all）模式：显示所有可用 Skills。
- 被 @ 提及的 Skill 会以标签形式显示在输入框下方，可点击移除。
- 切换智能体时，系统自动清理不允许的 Skill 标签（根据新智能体的 Skills 配置过滤）。

> 提示：Skills 依赖后端沙箱环境，沙箱未启用时整个 Skills 功能区域不显示。Skills 指令会注入到 Agent 的系统提示词中，增加每次对话的 token 消耗。

## 进阶用法

### 提示词模板

智能体编辑器为每种提示词类型提供了预设模板，可通过输入框右下角的模板选择器快速选用。模板包括：

- **系统提示词模板**：按快速回答和智能推理模式分别提供
- **上下文模板**：知识库内容的格式化模板
- **意图提示词模板**：各意图场景的预设提示词
- **改写提示词模板**：问题改写的系统和用户提示词
- **检索兜底模板**：固定回复和模型生成的兜底提示词

选择模板后会自动填入对应内容，可在此基础上自定义修改。

### 查询扩展原理

查询扩展不使用 LLM，而是通过本地文本处理自动生成查询变体：

1. 提取关键词：去除停用词，只保留关键词
2. 提取引号短语：提取引号内的内容作为独立查询
3. 按分隔符拆分：按标点符号拆分，取较长的片段
4. 去除疑问词：去掉开头的疑问词（什么是、如何、怎么等）

最多生成 5 个查询变体，并发检索后合并结果。

## 常见问题

### Q1：系统提示词填什么内容比较好？

建议包含三个部分：① 角色定位（如"你是一个专业的客服助手"）；② 回答要求（如"使用简洁专业的语言，优先引用知识库内容"）；③ 禁止行为（如"不要编造信息，不确定时说明无法回答"）。

### Q2：温度参数怎么调？

温度控制输出的随机性：0 最确定（适合事实性问答），1 最随机（适合创意生成）。知识库问答建议 0.3-0.7，创意任务建议 0.7-1.0。

### Q3：什么时候开启查询扩展？

查询扩展在初始检索结果较少时自动触发，通过提取关键词和拆分问题来增加召回。大多数场景建议保持开启，如果知识库内容精准且查询明确，可考虑关闭以减少处理时间。

### Q4：重排模型是必须的吗？

有 RAG 类型知识库时为必填。重排序模型对初步检索结果进行二次排序，将最相关的内容排到前面，显著提升回答质量。建议选择系统中已配置的 Rerank 模型。

### Q5：开启联网搜索会增加多少成本？

联网搜索会产生额外的搜索 API 调用费用，具体取决于搜索引擎提供商的计费方式。自动抓取页面内容还会增加网络请求和处理时间。建议仅在需要回答时效性问题或知识库未覆盖的领域时开启。

### Q6：Skills 和工具有什么区别？

工具是 Agent 可调用的原子能力（如搜索、读取文件），Skills 是更高层的专业知识模块（包含指令、脚本和参考文档）。一个 Skill 可能会指导 Agent 使用多个工具来完成复杂任务。Skills 在对话中通过 @ 提及方式按需加载。

### Q7：问题推荐的「混合」模式是什么意思？

混合模式结合了运营配置和知识库两种来源：优先展示运营配置的固定问题，不足时用知识库自动生成的问题补充。这样既保证了推荐问题的业务相关性，又能根据知识库内容动态更新。
